# LIP-033: Persistent live code

- **Status:** Final
- **Author:** Vijay Neelakantan
- **Date:** 2026-10-02

## Motivation

A one-shot program loses its reactive Information graph when its VM exits.
Hosts need to supply evidence later without rerunning top-level effects.

## Specification

- `live_register("name", information_value)` retains one root or derived
  Information value under a unique literal name and returns the same live
  value. A host observes registered roots and inspects any registered value.
- A live host runs top-level code once. Later observations use the existing
  transactional `observe` operation and recompute affected pure dependencies.
  Reads and `measure` do not publish a revision. There is no event handler.
- Each host process owns its handles and bytecode. Instances pass through
  `LIVE`, `QUIESCENT`, `SUSPENDED`, `FAILED`, and `DELETED`. Suspended evidence
  queues FIFO within 64 MiB and the instance memory budget. Resume reports
  each outcome. Invalid evidence does not publish a revision or block later
  events. Terminal VM failure stops processing; inspection remains available.
- CLI, Rust, and Python worker hosts share these operations. Evidence accepts
  definite JSON, explicit unweighted Possibility subsets, and existing tagged
  finite values. Unknown or deleted handles return `LANA_ERR_NOT_FOUND`.
- The builtin uses `HOST_CALL` ID 221 and existing LABC v5 Core semantics.
  No LABC format version changes.

## Rationale

Retaining the VM and named graph nodes preserves existing dependency identity,
provenance, and transactional observation. Replaying source would repeat
effects and produce different identities.

## Compatibility

`lana run` remains one-shot. Existing source and LABC v1-v6 keep their
behavior. A source program using `live_register` emits LABC v5; the loader
continues to accept v1-v6. Handles are process-local and have no persistence
or cross-process capability.

## Test coverage

Source fixtures and Rust, CLI, worker, and Python checks cover registration,
retained roots and bytecode, derived recomputation, inspection purity, FIFO
resume, evidence failures, queue limits, deletion, and host shutdown.
