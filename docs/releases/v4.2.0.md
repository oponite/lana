# Lana 4.2.0 local candidate

This minor release adds decimal exponent literals and tightens path
sampling semantics, and carries a robustness and hardening pass. Published
LABC formats, store encoding, and supported integrations are preserved.

Language and semantics (first released here; developed after 4.1.0):

- Decimal number literals accept an `e` or `E` exponent with an optional sign
  and required digits (`1e-5`, `2.5E+3`). An incomplete exponent is a lexical
  error. This is new source syntax; see `docs/spec/SYNTAX.md`.
- Paths from an unweighted guard remain unweighted, and `sample` on them now
  returns `LANA_ERR_UNSUPPORTED_OPERATION`. Weighted guards retain their branch
  probabilities through pure operations.
- Tensor operations on unaligned state views take the checked path instead of
  the aligned fast path.

Robustness: bootstrap resource accounting, bounded bytecode file ingress,
store publication and uncertain outcomes, and current TLS dependencies (no
advisories affected the previous versions). Execution fuzzing found legacy
function-frame sizing crashes; inputs are preserved as regressions and
cross-boundary frames and `ASYNC` argument ranges are sized safely.

Security: store journals now reject symlinks, non-regular files, and shared
hard links. Under the trust model in `SECURITY.md` (trusted programs and
clients, user-owned store directories) this is defense in depth, so no
advisory is issued. Resource-limit fixes are robustness fixes: Lana does not
support running untrusted source or bytecode.

It removes unused internal compiler code and regenerates the checked bootstrap.
Benchmark schema 2 measures precompiled CLI execution separately from compilation.

The base commit is `4ccfc32b99c41656f3a5649e9108963e75759380` (published
4.1.0 is `4e1606a390f44778029ff45bf0b8af7ff9b41272`).
The implementation is uncommitted; no release tag, publication, or tap update
is authorized by this local qualification run.

The exact working-source file hashes, host/toolchain identity, per-command
exit statuses, raw logs, archive checksums, and benchmark samples are recorded
in `/tmp/lana-4.2.0-qualification/`. `manifest.json` identifies the candidate;
`results.jsonl` records qualification commands. A failed or missing gate stays
open. Historical results do not qualify this candidate.

Required gates: the complete build/source/Rust suites and repeated bootstrap;
both fuzz targets for 600 seconds each (with a 4096 MB RSS limit); a clean universal install executing
both architecture slices; Python/MCP/Jupyter, actual WASM, real editors and
clean checksummed archives; paired Release measurements against local 3.0.2,
published 4.0.0, and published 4.1.0. The required 3.0.2 warm ratios
must not exceed 1.05. First calls are reported separately.

The dead-code review covers compiler, VM/runtime, tooling, integrations,
tests, configuration, and packaging. Public exports, standard-library APIs,
legacy bytecode behavior, and test-used constructors are deliberately retained.
The checked bootstrap is generated; its diff reflects removed functions and
updated internal registry indexes rather than a bytecode format change.

A clean committed candidate, protected tag, tagged CI, publication, and public
artifact/tap verification remain separate. Signing, notarization, and Homebrew
Core submission remain deferred.
