# LIP-011: Reverse-mode automatic differentiation over the derivation DAG

- **Status:** Final
- **Author:** Vijay
- **Date:** 2026-09-05

## Motivation

Learning is gradient descent, and gradient descent is automatic differentiation.
Python gets autodiff from PyTorch/JAX, but its tape is a throwaway: the forward
pass records a graph, the backward pass consumes it, and the graph is discarded.
You cannot ask *which input produced which gradient*, replay the gradient, or
audit it — the thing that made learning possible is gone the moment it is used.

Lana already threads a provenance DAG on every value (`spec/EVIDENCE.md`:
`LanaDerivation` / `Derivation` with an `inputs[]` graph). Reverse-mode autodiff
is literally the derivative of that DAG: the forward pass *is* the DAG Lana
already records, and the backward pass walks it in reverse, accumulating
gradients. So Lana gets gradients **and** provenance/audit of every gradient for
free — the tape is not throwaway, it is the audit trail.

This LIP makes `grad` a first-class operation over pure programs. It is the
prerequisite that LIP-006 (training), LIP-007 (differentiable STATE tensors),
and LIP-009 (variational inference) all build on.

## Specification

### 1. The `grad` operation

```lana
let g = grad(f)(x);        // gradient of scalar-output f at x
let j = vjp(f)(x, v);      // vector-Jacobian product: vᵀ · J_f(x)
```

- `f` is a **pure** function over tensors (LIP-004): `f(x) -> number` for
  `grad`, `f(x) -> tensor` for `vjp`. The compiler's existing effect discipline
  (`pure`/`observation`/`stochastic`/`io`/`mutation` in
  `compiler/resolver.lana`) enforces purity; a non-pure `f` is a compile error.
- `grad(f)(x)` returns the gradient tensor, the same shape as `x`.
- `vjp(f)(x, v)` returns the vector-Jacobian product for vector-valued `f`; it
  is the general form, `grad` is the scalar-output special case.

### 2. The tape is the derivation DAG

- The forward pass records the derivation DAG that every value already carries
  (`LanaDerivation.inputs[]` / `Derivation.inputs`). No separate tape is built.
- The backward pass walks that DAG in reverse, accumulating gradients into the
  input tensors by each operation's reverse-mode rule.
- The gradient is a tensor (LIP-004); the tape is released after the backward
  pass, but the gradient's own derivation retains the provenance (see §4).

### 3. Differentiable primitives

- **Core (this LIP).** The LIP-004 tensor operations — element-wise `+ - * /`,
  `matmul`, reductions (`sum`, `mean`) — are differentiable primitives with
  standard reverse-mode rules. This core depends only on LIP-004.
- **Extension (post-011).** The LIP-007 STATE operations — `append`, `measure`,
  `transform` — are differentiable primitives with the exact rules specified
  there; they are added after this LIP's core, not a dependency of it.
- A program is differentiable if it is a composition of these primitives and
  pure control flow; the compiler rejects a `grad` over a non-differentiable
  operation.

### 4. Provenance, replay, and audit

- Every gradient is a value with provenance: its derivation records *which input
  produced which gradient*, so the gradient is auditable exactly like the value
  it differentiates.
- Deterministic replay (§9.7.5) covers the gradient: the same
  `(seed, inputs, version)` reproduces the same gradient bytes.
- The gradient's provenance is the "beat": Python's tape is discarded, Lana's
  is retained as the audit trail of the computation that produced the gradient.

### 5. Errors

| Condition | Error |
|---|---|
| `f` not a function, or wrong arity | `LANA_ERR_TYPE` |
| `f` not pure (has observation/stochastic/io/mutation effects) | compile error |
| `x`/`v` not a tensor, or shape mismatch | `LANA_ERR_TYPE` |
| `grad` over a non-differentiable operation | compile error |
| non-finite gradient | `LANA_ERR_INVALID_PARAMETERS` |

## Rationale

- **The tape is the DAG, not a throwaway.** Lana already records a provenance
  DAG on every value; reverse-mode autodiff is the derivative of that DAG. No
  new graph structure is invented — the backward pass reuses the `inputs[]`
  graph that provenance already walks.
- **Match + beat.** PyTorch/JAX match on the mechanics (reverse-mode over
  tensors); Lana beats on audit — the gradient carries provenance and is
  replayable, because the tape is the audit trail rather than a discarded
  intermediate.
- **A prerequisite, not a component.** Autodiff is general-purpose differentiable
  programming, not training-specific. Splitting it out (rather than folding it
  into LIP-006) lets LIP-006, LIP-007, and LIP-009 cite one clean prerequisite
  and keeps each LIP's scope single.

## Compatibility

- **No new `ValueType` tag** — the gradient is a `VAL_TENSOR` (or a structured
  value over it).
- **No LABC format change** — `grad` and `vjp` are host calls, so the bytecode
  version stays `2`.
- **New host-call IDs** `grad`, `vjp` appended to `LanaHostCallId` (C and Rust
  must match).
- **Depends on LIP-004** (tensor) only. The STATE primitives of LIP-007 are
  differentiable through this LIP as a post-011 extension, not a dependency.
- **Resource limits unchanged**; the backward pass and gradient buffers count
  against the 256 MiB limit.

## Test coverage

- `grad` of element-wise, `matmul`, and reduction compositions against
  hand-computed gradients.
- `vjp` matches `grad` for scalar output; `vjp` matches finite differences for
  vector output.
- Gradient checks (finite differences) for the LIP-007 STATE primitives.
- Compile error for a non-pure `f` and for `grad` over a non-differentiable
  operation.
- Provenance: a gradient's derivation traces to its input.
- Replay: two runs with the same seed produce byte-identical gradients.
- Differential conformance: byte-identical C11 vs Rust output for a fixed seed.
