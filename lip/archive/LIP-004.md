# LIP-004: First-class tensor and vectorized operations

- **Status:** Final
- **Author:** Vijay
- **Date:** 2026-09-05

## Motivation

The N-qubit density-operator substrate (`papers/semantics-2.md` §1–6) represents
a state as a dense `d × d` complex matrix, `d = 2^N ≤ 1024`. Exposing that
substrate as a general surface (LIP-005) requires matrix multiply, trace, and
reductions over those matrices. Run as scalar VM instructions, a single
`1024 × 1024` complex matmul is on the order of a billion instructions — far
past the 50,000,000-instruction budget and unusably slow even where it fits.

Lana has no numeric array type today: `LanaArray` (`vm/include/value.h:234`) is
a boxed `Value *items` vector, not a contiguous numeric buffer, and there is no
BLAS/GPU backend. This is the single biggest gap between Lana and the numeric
stacks it is meant to interoperate with.

This LIP adds a first-class tensor — an N-dimensional numeric array with
vectorized arithmetic, matmul, reductions, and indexing — compiled to a
BLAS/GPU backend rather than run on the scalar VM. Lana already compiles to
C11, so this is codegen plus a native runtime backend, not a VM rewrite. The
goal is to match, not beat, what PyTorch and JAX already provide.

## Specification

### 1. Value type

A new `ValueType` tag `VAL_TENSOR` with a contiguous numeric buffer:

```c
typedef struct {
    size_t ndim;
    size_t *shape;      /* length ndim */
    size_t *strides;    /* length ndim, row-major */
    bool is_complex;
    double *data;       /* length prod(shape) * (is_complex ? 2 : 1) */
    size_t offset;      /* first element, in elements (0 for a base tensor) */
    LanaTensor *base;   /* source tensor for a view, NULL for a base tensor */
} LanaTensor;
```

- `dtype` is `number` (IEEE 754 binary64) or `complex` (a pair of binary64,
  real then imaginary, interleaved).
- `ndim ≥ 0`; a 0-d tensor is a scalar. `ndim ≤ 32`.
- A base tensor's buffer is contiguous and row-major, so BLAS sees a plain
  pointer. A slicing view shares that buffer: it carries an `offset` into the
  base buffer and per-axis `strides` that may be non-contiguous. The `base`
  pointer roots the source tensor so the shared buffer outlives every view.
  Element access in every tensor operation goes through `offset` and
  `strides`; nothing assumes a tensor is contiguous.

### 2. Construction

```lana
let a = tensor([1.0, 2.0, 3.0]);          // 1-d, number
let b = tensor([[1.0, 0.0], [0.0, 1.0]]); // 2-d, number
let c = zeros([2, 3]);                     // 2×3, number
let d = ones([2, 2]);                      // 2×2, number
let e = eye(3);                            // 3×3 identity, number
let f = tensor_complex([1.0, 0.0], [0.0, 1.0]); // complex from re/im parts
```

- `tensor(...)` accepts a nested array literal of numbers (or of `[re, im]`
  pairs for complex) and infers the shape; ragged input is rejected.
- `zeros(shape)`, `ones(shape)`, `eye(n)` take a shape array (or a single
  integer for `eye`).
- `shape(t)` returns the shape as an array; `ndim(t)` returns the rank;
  `dtype(t)` returns `"number"` or `"complex"`.

### 3. Vectorized operations

Element-wise arithmetic reuses the ordinary numeric operators, lifted
element-wise (this is ordinary numeric semantics, not a probabilistic
operation, so it does not violate SYNTAX-3):

```lana
let s = a + b;   // element-wise add
let d = a - b;   // element-wise subtract
let p = a * b;   // element-wise multiply
let q = a / b;   // element-wise divide
```

Broadcasting follows NumPy rules: shapes are aligned from the right; a
dimension of size 1 broadcasts to the other operand's size; missing leading
dimensions are treated as 1. Incompatible shapes raise
`LANA_ERR_INVALID_PARAMETERS`.

Non-obvious operations use explicit keywords (SYNTAX-3, SYNTAX-5):

```lana
let c = matmul(a, b);   // matrix product, not element-wise
let s = sum(t);         // reduction over all elements
let m = mean(t);        // arithmetic mean
let x = max(t);         // maximum element
let n = min(t);         // minimum element
let r = sum(t, axis: 0); // reduction along an axis (optional axis)
```

- `matmul` follows NumPy semantics: 1-d × 1-d is a dot product, 1-d × 2-d and
  2-d × 1-d are vector-matrix, and N-d × M-d contracts the last axis of the
  left with the second-to-last of the right. Incompatible shapes raise
  `LANA_ERR_INVALID_PARAMETERS`.
- Full reductions return a `number`, or a rank-zero complex tensor for complex
  `sum`/`mean`; `max`/`min` on a complex tensor raise `LANA_ERR_TYPE`.
  An axis reduction removes the selected dimension and always returns a tensor.
  Negative axes count from the last dimension. Axis and empty-domain errors
  follow `spec/SPEC.md`.

### 4. Indexing and slicing

```lana
let x = t[0];        // first row (1-d view)
let y = t[1, 2];     // scalar element
let z = t[1:3];      // slice rows 1..2 (end-exclusive)
let w = t[1:3, 0];   // mixed: slice axis 0, integer axis 1
```

- An index expression holds a comma-separated list of positions, one per axis
  from axis 0. A position is either an integer expression or a slice
  `start:end` (end-exclusive). Fewer positions than the rank keep the
  remaining trailing axes whole (as full slices).
- An integer position reduces the rank by one. Negative integers count from
  the end (`i + dim`). An integer position that is not a number, is not
  integer-valued, or is non-finite raises `LANA_ERR_TYPE`; an in-range-adjusted
  integer outside `[0, dim)` raises `LANA_ERR_KEY`. A full set of integer
  positions returns a scalar: a `number` for a real tensor, or a rank-zero
  complex tensor for a complex tensor (the established complex-scalar form).
- A slice position preserves the rank. Both bounds must be integer-valued
  numbers (else `LANA_ERR_TYPE`). Negative bounds count from the end, then
  clamp to `[0, dim]`; `start > end` yields an empty dimension. Slice bounds
  never raise range errors — out-of-range bounds clamp, matching NumPy.
- The result of any position list that is not fully integer is a **view**: the
  same buffer, `is_complex`, and base tensor, with derived shape, strides, and
  offset. No copy is made for basic indexing and slicing.
- Views are read-only. This LIP does not specify tensor element assignment;
  `index_set` on a tensor raises `LANA_ERR_TYPE` until a LIP specifies
  mutation through views.
- Arithmetic, `matmul`, and reductions accept strided views; every element
  access respects offset and strides, and full reductions traverse a
  strided tensor rather than assuming a contiguous buffer.
- More positions than the rank raise `LANA_ERR_INVALID_PARAMETERS`; a slice
  position that is not a `[start, end]` pair raises `LANA_ERR_TYPE`.
- Array, map, and tensor indexing share the `index_get` host call. A tensor
  source accepts a single number (one integer position) or an array of
  positions (each a number or a `[start, end]` pair). Existing single-index
  programs compile to the identical host call as before.

### 5. Backend

- **Baseline:** `matmul` lowers to the platform CBLAS `dgemm`/`zgemm` family
  behind a single dispatch point (`vm/c/backend.c`, mirrored in
  `vm/rust/lana-vm/src/backend.rs`). One-dimensional operands are promoted to
  matrices (a `(k,)` vector is a `(1, k)` or `(k, 1)` matrix as position
  dictates), and each batch element issues one call into a contiguous,
  row-major result slice. Both VMs must use the same backend on a given
  platform so C/Rust differential byte identity holds: Apple platforms link
  the Accelerate framework; a build without a linked BLAS falls back to the
  native loop through the same dispatch point (exact for integer-valued
  results; not guaranteed bit-identical to BLAS otherwise).
- **Views pack for BLAS:** a `matmul` operand whose core is not row-major
  contiguous is first gathered into contiguous scratch; the scratch is a
  tensor buffer for accounting purposes and counts against the memory limit.
- **Native elsewhere:** element-wise arithmetic, indexing, and reductions
  remain native loops (not scalar VM instructions). Reductions deliberately
  do not use BLAS: their error contract — non-finite rejection, complex
  `max`/`min` typing, per-axis empty rules — has no BLAS equivalent.
- **Optional GPU:** a pluggable backend behind the same dispatch point; the
  language contract is backend-independent. GPU is not a hard dependency.
  The 2.1 milestone permits explicit approximate GPU execution with a named
  precision and documented tolerance. Binary64 CPU inputs are never silently
  downcast. Record backend/precision in provenance; approximate GPU results do
  not claim bitwise CPU replay. Software binary64 Metal is not required.
- Tensor operations lower to **host calls** (`OP_HOST_CALL`), not dedicated
  opcodes, consistent with `semantics-2.md` §8 ("a library over the
  general-purpose core") and the `surprisal` precedent in `spec/ML.md`.
- The compiler (`compiler/emitter.lana`) emits these host calls; the VM links a
  native tensor backend. No tensor operation is executed as a scalar VM loop.

### 6. Errors

| Condition | Error |
|---|---|
| ragged `tensor(...)` literal | `LANA_ERR_INVALID_PARAMETERS` |
| incompatible broadcast / matmul shapes | `LANA_ERR_INVALID_PARAMETERS` |
| `max`/`min` on a complex tensor | `LANA_ERR_TYPE` |
| non-number, non-integer, or non-finite index position or slice bound | `LANA_ERR_TYPE` |
| out-of-range integer index position | `LANA_ERR_KEY` |
| more index positions than the rank | `LANA_ERR_INVALID_PARAMETERS` |
| slice position not a `[start, end]` pair | `LANA_ERR_TYPE` |
| `index_set` on a tensor | `LANA_ERR_TYPE` |
| non-finite element in a reduction | `LANA_ERR_INVALID_PARAMETERS` |

## Rationale

- **BLAS/GPU, not scalar VM.** A dense `d × d` matmul is the substrate's hot
  path. Native BLAS is the difference between microseconds and billions of
  instructions; there is no scalar-VM formulation that is acceptable.
- **A general-purpose tensor, not quantum-specific matrices.** The tensor is
  useful for every numeric workload in Lana, not only the density-operator
  substrate. Keeping it general avoids baking quantum semantics into the core.
- **Host calls, not opcodes.** This follows the stated 2.0 direction
  (`semantics-2.md` §8, `vijay-docs/lana_arch_current_future.md`) to demote
  domain operations to a library over the general-purpose core. It also keeps
  the LABC encoding stable.
- **Match, not beat.** The semantics deliberately mirror NumPy/PyTorch/JAX
  (broadcasting, `matmul` rules, row-major layout) so the surface is familiar
  and the backend can be a thin wrapper over existing BLAS.

## Compatibility

- **New value type** `VAL_TENSOR`; existing `VAL_ARRAY` is unchanged.
- **No LABC format change** — tensor operations are host calls, so the bytecode
  version stays `2`.
- **New host-call IDs** appended to `LanaHostCallId` (C and Rust must match).
- **New native dependency** (CBLAS/LAPACK) for the C11 VM and the Rust VM; the
  build must link it. GPU is optional and off by default.
- **Resource limits unchanged** (256 MiB, 50,000,000 instructions); a tensor's
  buffer counts against the memory limit, and so does every per-operation
  temporary: shape/stride scratch and BLAS packing buffers route through the
  VM allocator in both VMs. A native tensor call is bounded by its operand
  buffers (each under the memory limit) and is not interruptible mid-call;
  mid-call interruption is recorded as a v3 suspension concern, not a 2.1
  gate.

## Test coverage

- `matmul` against known results (dot, vector-matrix, matrix-matrix, batched).
- Broadcasting: compatible and incompatible shapes.
- Reductions: `sum`/`mean`/`max`/`min` over 0-d, 1-d, 2-d, and axis-reduced
  tensors; complex `sum`/`mean`; `max`/`min` on complex raises.
- Indexing/slicing: element, row, slice, mixed int/slice, negative indices and
  bounds, clamped slice bounds, empty slices, views of views, stride-aware
  arithmetic/reductions over views, out-of-range, too many positions,
  non-integer positions, `index_set` rejection, and lifetime (a view keeps the
  base buffer alive under GC).
- Construction: `tensor`, `zeros`, `ones`, `eye`, `tensor_complex`; ragged
  input rejected.
- Differential conformance: byte-identical C11 vs Rust output for every op.
