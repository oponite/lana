# LIP-016: Standard library — batteries included

- **Status:** Final
- **Author:** Vijay
- **Date:** 2026-09-05

## Motivation

`stdlib/` is empty. Every program that needs to split a string, parse JSON,
format a number, or iterate a collection re-implements it by hand over the
VM's host calls. Python's universality is not its syntax — it is "batteries
included": a standard library broad enough that most programs need no third
party. Lana has the host-call primitives (`map_new`, `array_length`,
`directory_list`, `hash_update`, and the rest) but no composed, portable
library layered over them.

This LIP establishes the Lana standard library as a Lana-level library over
the existing host calls, with a reserved import namespace, a conformance bar,
and a versioning contract. It adds no VM semantics and no LABC change; it is
the highest-leverage universality move because it turns a language into a
toolkit.

## Specification

### 1. Namespace and layout

- Standard-library modules live in `stdlib/` and are imported through a
  reserved `std/` prefix:

  ```lana
  import std/string;
  import std/json;
  import std/math;
  ```

- The `std/` prefix resolves to the installed standard library, not to a
  relative path. Relative imports (`import ./foo.lana`) are unchanged.
- A module is a single `.lana` file; submodules use `std/string/format` style
  paths where a module grows large enough to warrant splitting.

### 2. Initial modules

The first release ships these modules, each pure Lana over host calls unless
noted:

| Module | Contents |
|---|---|
| `std/string` | `split`, `join`, `trim`, `starts_with`, `ends_with`, `contains`, `replace`, `to_upper`, `to_lower`, `substring` |
| `std/regex` | `regex_compile`, `regex_match`, `regex_search`, `regex_replace` (see LIP-021) |
| `std/json` | `json_parse`, `json_stringify` (see LIP-023) |
| `std/math` | `abs`, `sqrt`, `pow`, `exp`, `log`, `sin`, `cos`, `floor`, `ceil`, `round`, `min`, `max`, `clamp` |
| `std/collections` | set, iterator, and map helpers (see LIP-022) |
| `std/datetime` | `now`, `parse_timestamp`, `format_timestamp`, `add_duration` |
| `std/iterators` | `iter`, `map`, `filter`, `reduce`, `zip`, `enumerate` (see LIP-022) |
| `std/random` | `random_seed`, `random_int`, `random_float`, `random_choice` |
| `std/testing` | `assert_eq`, `assert_true`, `assert_raises`, `test` |
| `std/ml` | uncertainty-aware regression, dense networks, Kalman/HMM, boosted trees, and jump diffusion (see LIP-028) |

### 3. Conformance bar

- Every stdlib function is `pure` unless it declares an effect (`io`,
  `stochastic`, `external_call`). A function that reads the clock or draws a
  random value declares its effect explicitly.
- Every stdlib value carries provenance like any other Lana value; stdlib
  functions do not bypass the derivation DAG.
- No stdlib function may exceed the compiler resource limits (256 MiB,
  50,000,000 instructions) on its documented inputs.

### 4. Versioning

- The standard library is versioned with the language release. `lana.lock`
  records the content identity of the stdlib modules a program imports, so a
  build is reproducible against the exact stdlib it was written for.
- A stdlib module is not part of the language contract until accepted through
  the LIP process; the reserved `std/` prefix is the only contract this LIP
  adds.

## Rationale

- **Layer over host calls, not new opcodes.** This follows the stated 2.0
  direction (`papers/semantics-2.md` §8) to demote domain operations to a
  library over the general-purpose core. It keeps LABC v2 stable.
- **Reserved prefix, not a new import syntax.** A `std/` prefix is the minimal
  change that distinguishes the standard library from user code without
  inventing a package syntax (which is LIP-017's job).
- **Effect-declaring, not effect-hiding.** A stdlib function that reads the
  clock or draws randomness must say so, preserving Lana's "no hidden state"
  contract.

## Compatibility

- **No LABC change** — the standard library is source-level Lana.
- **New reserved import prefix** `std/`; relative imports are unchanged.
- **No VM change**; the library runs on the existing host-call surface.
- **Resource limits unchanged.**

## Test coverage

- A unit test per stdlib function, in `tests/unit/` or a stdlib test tree.
- Effect-declaration conformance: a test that a clock-reading function is
  rejected when called from a `pure` context.
- Provenance conformance: a test that a stdlib-derived value retains its
  derivation inputs.
- Reproducibility: a test that `lana.lock` pins the stdlib content identity and
  a rebuild from the lockfile is byte-identical.
