# LIP-007: Differentiable STATE tensors

- **Status:** Draft
- **Author:** Vijay
- **Date:** 2026-09-05

## Motivation

A tensor whose elements are density matrices — with differentiable APPEND,
MEASURE, and TRANSFORM — is a model class Python cannot express natively. In
Python, a density matrix is a NumPy array with no probabilistic semantics; the
operations that give it meaning (evidence combination, observation, evolution)
are hand-written and not differentiable through a training loop.

Lana's whole reason to exist is probabilistic semantics. This LIP makes that
semantics the *substrate of the network*, not a bolt-on: model weights and
activations are density matrices, and the operations that combine, observe, and
evolve them are the same first-class, differentiable operations as everywhere
else. A network built this way is a probabilistic computation end to end — its
forward pass is evidence combination and measurement, and its training (LIP-006)
is gradient descent over that computation.

This is the "in general" killer: it is not a special-case layer, but a general
tensor type whose elements are STATEs, usable anywhere a tensor is.

## Specification

### 1. STATE tensor type

A tensor (LIP-004) with a `state` dtype: each element is an N-qubit density
matrix (LIP-005 `VAL_NQUBIT_STATE`), a `d × d` complex matrix with `d = 2^N`.

- The tensor has shape `[s_1, ..., s_k]`; each element is a `d × d` matrix, so
  the underlying buffer is `[s_1, ..., s_k, d, d]` complex.
- The `state` dtype enforces, per element, Hermitian, positive semidefinite, and
  unit trace (LIP-005 §1.2). `N ≤ 10`.
- Construction:

  ```lana
  let s = state_tensor([[[0.5, 0.0], [0.0, 0.5]], [[1.0, 0.0], [0.0, 0.0]]]);
  ```

  `state_tensor(...)` accepts a nested literal of density matrices and infers
  the shape and `N`; each element is validated as a density operator.

### 2. Differentiable STATE operations

The STATE operations apply element-wise over the tensor and are differentiable
primitives in the autodiff tape (LIP-011):

```lana
let c = append(a, b);          // element-wise distribution-valued combination
let q = measure(s, povm);      // element-wise outcome probability
let t = transform(s, chan);    // element-wise channel application
```

- **APPEND** — the distribution-valued APPEND of `papers/semantics.md` §4
  (relationship-aware evidence combination), applied element-wise over the
  STATE tensor. It preserves the explicit relationship rules and never discards
  a distribution; it is not a scalar `p_C = 1 - (1-p_A)(1-p_B)` reduction. Its
  reverse-mode rule is the derivative of the distribution-valued operation
  (LIP-011).
- **MEASURE** — `measure(s, povm)` returns `q_B = Tr(ρ E)` for each POVM element
  `E` (LIP-005 §3.1). Linear in `ρ`: `∂q_B/∂ρ = E`.
- **TRANSFORM** — `Φ(ρ) = Σ_k K_k ρ K_k†` (LIP-005 §4.1). Linear in `ρ`:
  `∂Φ/∂ρ = Σ_k K_k (·) K_k†`; differentiable in the Kraus operators `K_k` when
  the channel is itself a learned parameter.

All LIP-005 operations (`tensor_product`, `partial_trace`, `expect`, `mix`,
`trace_distance`) are likewise differentiable primitives; APPEND, MEASURE, and
TRANSFORM are the headline three because they are the probabilistic core.

### 3. Integration with training

A STATE tensor is an ordinary tensor value, so it can be a model's weights or
activations and is trained by LIP-006:

```lana
let result = train(model, data, loss, adam(learning_rate: 0.001), initial_params, epochs: 10);
```

- The forward pass composes differentiable STATE operations; the backward pass
  flows gradients through APPEND/MEASURE/TRANSFORM into the density-matrix
  parameters.
- The trained parameters are STATE tensors; their provenance, replay, and
  uncertainty are carried exactly as in LIP-006.

### 4. Errors

| Condition | Error |
|---|---|
| `state_tensor` element not Hermitian / PSD / unit trace | `LANA_ERR_INVALID_STATE` |
| `N > 10` (d > 1024) | `LANA_ERR_INVALID_PARAMETERS` |
| element-wise op on mismatched shapes | `LANA_ERR_INVALID_PARAMETERS` |
| `measure`/`transform` on a non-`state` tensor | `LANA_ERR_TYPE` |

## Rationale

- **Beat, in general.** A density-matrix tensor with differentiable
  probabilistic operations is a general type, not a bespoke layer. It composes
  with every other tensor operation, so probabilistic models are built from the
  same primitives as ordinary ones.
- **Probabilistic semantics as substrate.** APPEND, MEASURE, and TRANSFORM are
  already the language's core operations; making them differentiable means the
  network's forward pass *is* the probabilistic computation, not a numeric
  approximation of one.
- **Differentiability is inherited.** The STATE operations are linear or
  low-order nonlinear, so their reverse-mode rules are small and exact; the
  autodiff machinery of LIP-011 supplies the tape and accumulation.

## Compatibility

- **New tensor dtype** `state` (LIP-004); no new `ValueType` tag — a STATE
  tensor is a `VAL_TENSOR` with a `state` dtype flag.
- **No LABC format change** — operations are host calls, so the bytecode
  version stays `2`.
- **Depends on LIP-004** (tensor), **LIP-005** (N-qubit STATE and operations),
  **LIP-011** (autodiff), and **LIP-006** (training).
- **Resource limits unchanged**; a STATE tensor's buffer counts against the
  256 MiB limit.

## Test coverage

- `state_tensor` construction and per-element validation (non-Hermitian,
  non-PSD, non-unit-trace rejected).
- Gradient checks (finite differences) for APPEND, MEASURE, and TRANSFORM.
- Element-wise semantics: `append`/`measure`/`transform` over a batch of
  states match the scalar results per element.
- End-to-end: train a small density-matrix model (e.g. a two-state classifier)
  and confirm the loss decreases and the run is replayable.
- Differential conformance: byte-identical C11 vs Rust output for a fixed seed.
