# LIP-031: Rust-only Lana 4.0 distribution

- **Status:** Final
- **Author:** Lana maintainers
- **Date:** 2026-09-24

## Motivation

The Rust CLI, bytecode loader, VM, and runtime are canonical, but 3.x still
builds and ships a frozen C VM and native C APIs. Keeping both engines and
their release gates makes every change harder to verify.

## Specification

- Lana 4.0 distributes the Rust `lana` CLI and its self-hosted compiler
  bytecode. It does not distribute `lanavm`, `liblanaruntime`, `liblana_bridge`,
  `lana-ffi`, C headers, or the C evidence server.
- The Rust loader continues to accept published LABC v1-v5. Existing opcode
  numbers, host-call IDs, and resource limits do not change. Checked v1-v2
  fixtures replace live C comparison in conformance tests.
- The JSON bridge is the supported process integration boundary. A persistent
  Rust worker may reuse the same JSON result envelope for repeated calls. It
  starts a fresh VM for each call and never retries an ambiguous call.
- The SQLite and localhost HTTP_JSON adapter kinds remain available through
  Rust runtime host calls. SQLite opens read-only. HTTP_JSON accepts a port and
  a relative path and reads the existing `ok`/`evidence` envelope from
  `127.0.0.1`. Neither requires a C plugin.
- Lana programs may still use the separate, capability-gated native-library
  call feature for the bounded scalar signatures supported by the Rust VM.
  It does not expose a Lana C API.

## Rationale

One VM and one installed CLI remove duplicate behavior and build targets.
Static bytecode fixtures preserve published format checks without requiring a
second engine. A persistent process keeps repeated integration calls fast
without restoring a C ABI.

## Compatibility

The installed native ABI v1 and the incomplete Rust FFI contract in LIP-029
are retired in 4.0. LIP-029's record schema, authorization, execution, and
receipt rules remain in force; its C ABI negotiation and installed C consumer
requirements are superseded by this LIP. Existing C clients must migrate to
the JSON bridge. LABC v1-v5 files remain readable by the Rust loader.

## Test coverage

- Saved v1-v2 bytecode fixtures cover valid execution and malformed input.
- Compiler bootstrap remains byte-stable across two Rust VM runs.
- Python source and precompiled-bytecode calls preserve structured results.
- SQLite and HTTP_JSON success and failure paths run through Rust host calls.
- The release candidate builds, tests, installs, and runs without Lana-owned C
  sources or targets.
