# LIP-013: Typed model-graph DSL with compile-time shape checking

- **Status:** Draft
- **Author:** Vijay
- **Date:** 2026-09-05

## Motivation

Python's model definitions are untyped dicts and classes: a layer is a
`nn.Module` whose shapes are implicit, and a shape mismatch surfaces at runtime —
often deep in a training run, after a GPU-hour is spent. There is no way to say
"this layer's output feeds that layer's input" and have the compiler check it.

Lana already has the primitives this needs: ADTs (sum types), generics, and
pattern matching with exhaustiveness checking (`spec/ADT.md`). This LIP adds a
first-class way to declare a model architecture as a **typed ADT** — layers,
connections, and shapes — so a shape mismatch or a missing layer is a
compile-time error, not a runtime crash.

## Specification

### 1. Shape-typed tensors

A tensor (LIP-004) carries a compile-time shape parameter:

```lana
type Shape = Dims(Int, ...);          // a type-level list of dimensions
let x: Tensor<[2, 3]> = zeros([2, 3]); // shape is part of the type
```

- `Tensor<S>` is the tensor type parameterized by a shape `S`; `S` is a
  type-level list of dimensions (or a shape variable).
- The compiler tracks `S` through tensor operations (LIP-004): `matmul`,
  element-wise, and reductions refine the output shape from the input shapes.
- A shape is known at compile time when it is a literal or a shape variable
  bound by the model declaration; a runtime-only shape is a `Tensor<Dynamic>`.
- The shape parameter is a type-level list of integer literals (or a shape
  variable bound by the model declaration), not a full dependent type. It rides
  on the existing generic machinery (`spec/ADT.md`); HKT/GADTs are not required
  and are out of scope.

### 2. Layer ADTs

A layer is a typed ADT variant carrying its input and output shapes:

```lana
type Layer =
  | Dense(in: Shape, out: Shape, weights: Tensor<[in, out]>)
  | Conv(in: Shape, out: Shape, kernel: Shape)
  | Relu(shape: Shape);
```

- Each variant declares its input shape, output shape, and parameters.
- The parameter tensors' shapes are constrained by the variant's shapes, so a
  `Dense` whose `weights` do not match `[in, out]` is a compile error.

### 3. Model graph

A model is a typed ADT of layers and connections:

```lana
type Model =
  | Sequential(Layer, Layer)
  | Residual(Layer, Layer)
  | Branch(Layer, Layer, Layer);
```

- A connection is a variant field: `Sequential(a, b)` asserts that `a`'s output
  shape equals `b`'s input shape.
- The model is a value (`VAL_ADT`), so it is inspectable, replayable, and
  auditable like any other Lana value.

### 4. Compile-time shape checking

- The compiler checks every connection: the output shape of a layer must equal
  the input shape of the layer it feeds. A mismatch is a **compile error**.
- The check is structural, not a runtime assertion: it runs in the resolver
  (`compiler/resolver.lana`) before any code executes.
- A `Tensor<Dynamic>` connection defers the check to runtime and raises
  `LANA_ERR_INVALID_PARAMETERS` on mismatch — the explicit opt-out, never the
  default.

### 5. Exhaustiveness

- A model graph must be complete: the existing `match` exhaustiveness
  (`spec/ADT.md` §3.2) applies to the model ADT, so a missing layer or an
  unhandled connection is a compile error.
- `unknown` (the implicit variant of every ADT) must be handled explicitly, so
  an incomplete model cannot silently fall through.

### 6. Errors

| Condition | Error |
|---|---|
| connection shape mismatch (compile-time shape) | compile error |
| `Dense` weights not `[in, out]` | compile error |
| model `match` not exhaustive (missing layer/connection) | compile error |
| `Tensor<Dynamic>` connection mismatch at runtime | `LANA_ERR_INVALID_PARAMETERS` |
| non-tensor field where a tensor is declared | `LANA_ERR_TYPE` |

## Rationale

- **Catch it before the GPU-hour.** Python's shape errors surface at runtime,
  deep in a training run. Lana's shape checking runs in the resolver, so a
  mismatch is caught before any compute is spent.
- **Inherited, not invented.** ADTs, generics, and exhaustiveness already exist
  (`spec/ADT.md`); this LIP uses them to type model architectures. The shape
  parameter is the one new type-level construct, and it rides on the existing
  generic machinery.
- **The model is a value.** Because a model is a `VAL_ADT`, it is inspectable,
  replayable, and auditable — the same properties as every other Lana value, now
  applied to the architecture itself.
- **Explicit opt-out, not silent.** A runtime-only shape is `Tensor<Dynamic>`,
  an explicit declaration that the check is deferred — never a silent fallback.

## Compatibility

- **No new `ValueType` tag** — a model is a `VAL_ADT` (existing); the shape
  parameter is a type-level construct, not a runtime value.
- **No LABC format change** — the DSL lowers to the existing `ADT_BUILD` /
  `ADT_CASE` / `ADT_GET` opcodes; the shape check is a resolver pass. The
  bytecode version stays `2`.
- **Depends on LIP-004** (tensor) and the existing ADT/generics/pattern-matching
  machinery (`spec/ADT.md`). LIP-006 (training) is a consumer of the DSL, not a
  dependency of it.
- **Resource limits unchanged**; the model ADT counts against the 256 MiB limit.

## Test coverage

- A `Sequential` whose layers' shapes match compiles; a mismatch is a compile
  error.
- A `Dense` with weights not `[in, out]` is a compile error.
- A model `match` missing a layer/connection is a compile error (exhaustiveness).
- `Tensor<Dynamic>` defers the check and raises `LANA_ERR_INVALID_PARAMETERS` on
  a runtime mismatch.
- The model ADT is a value: it is inspectable and replayable.
- Differential conformance: byte-identical C11 vs Rust output for a fixed seed.
