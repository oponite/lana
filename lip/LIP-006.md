# LIP-006: Auditable, replayable training primitive

- **Status:** Draft
- **Author:** Vijay
- **Date:** 2026-09-05

## Motivation

A Python training loop is a black box: the optimizer mutates parameters in
place, the step history is not a value you can inspect, and nothing guarantees
that re-running the loop reproduces the same model. You cannot audit *what
happened at each step*, replay it deterministically, or carry uncertainty
through it.

Lana's values already carry provenance (`papers/semantics.md` §0.1,
`papers/semantics-2.md` §9.7), deterministic replay (§9.7.5), and uncertainty
(`Sample`, `Information`). A training primitive should be the same kind of
thing: a first-class, auditable, replayable, uncertainty-carrying computation.

This LIP adds `train(model, data, loss, optimizer, initial_params)` as a
first-class operation with Adam and SGD optimizers, where each step is a
derivation node carrying provenance, a fixed seed makes the whole run
byte-identical, and uncertain inputs carry uncertainty through the run (LIP-008). The goal is to **match** PyTorch/JAX on the
mechanics (autodiff, Adam/SGD) and **beat** them on auditability and replay —
because those are properties every Lana value already has.

## Specification

### 1. First-class values

- `VAL_OPTIMIZER` — an optimizer with a name and hyperparameters:

  ```lana
  let opt = sgd(learning_rate: 0.01, momentum: 0.9);
  let opt = adam(learning_rate: 0.001, beta1: 0.9, beta2: 0.999, epsilon: 1e-8);
  ```

- `model` and `loss` are ordinary Lana functions over tensors (LIP-004):
  `model(params, x) -> y`, `loss(y, target) -> number`.
- `data` is a dataset of `(x, target)` pairs; a `lazy` dataset (LIP-004 /
  `spec/DATASETS.md`) is accepted so batches stream without materializing the
  whole set.

### 2. Automatic differentiation

`train` requires the gradient of `loss` with respect to the model parameters.
Reverse-mode automatic differentiation is provided by LIP-011 (`grad`/`vjp`
over the derivation DAG), so `loss` is a plain function and gradients are
computed automatically. `train` composes `grad` over the batch loss; the
gradient's provenance and replay are inherited from LIP-011.

### 3. The `train` operation

```lana
let result = train(model, data, loss, optimizer, initial_params, epochs: 10, batch_size: 32);
```

- `train` is a first-class operation returning a `VAL_TRAINING_RESULT`, not a
  bare model.
- The loop iterates epochs × batches; each step computes the batch loss,
  backpropagates, and applies one optimizer update.
- `initial_params` is the explicit starting parameter tensor (or STATE tensor,
  LIP-005); training begins from it, never from an implicit zero or random
  initialization.
- `epochs` and `batch_size` are positive integer literals; `batch_size` may be
  omitted to use the full dataset per step.
- `train` is an authorized operation: it requires the `train` capability
  (LIP-012) and is denied before access when the capability is not granted.
- The result carries the trained parameters **and** the step history.
- The step history is an indexable value: `result.steps[i]` addresses the i-th
  step (parameters, optimizer state, and provenance at that step), so any step
  is a resumption point (LIP-014).

### 4. Provenance, replay, and uncertainty

- **Provenance.** Each step is a derivation node: its inputs are the batch
  identity, the pre-update parameters, and the gradient; its output is the
  post-update parameters. The step history is a value, so the whole run is
  auditable — you can ask *which batch produced which gradient produced which
  update*.
- **Deterministic replay.** The run is seeded; given the same
  `(seed, inputs, version)`, the output bytes are identical (§9.7.5). Batch
  order, RNG draws, and floating-point evaluation are fixed.
- **Uncertainty (LIP-008).** A training result over uncertain operands carries
  uncertainty per LIP-008; `train` itself does not invent uncertainty for
  ordinary (certain) tensors. The loss trajectory and final parameters are
  ordinary values unless the inputs are uncertain.

### 5. Errors

| Condition | Error |
|---|---|
| `loss` not a function, or wrong arity | `LANA_ERR_TYPE` |
| `optimizer` hyperparameter out of range / non-finite | `LANA_ERR_INVALID_PARAMETERS` |
| `epochs`/`batch_size` not positive integers | `LANA_ERR_INVALID_PARAMETERS` |
| `data` empty | `LANA_ERR_INVALID_PARAMETERS` |
| `train` without the `train` capability | `LANA_ERR_CAPABILITY` (denied before access) |
| non-finite loss or gradient | `LANA_ERR_INVALID_PARAMETERS` |

## Rationale

- **First-class, not a library loop.** Making `train` a value-producing
  operation is what lets the step history be a value you can inspect, replay,
  and diff. A user-written loop over host calls would not carry provenance
  automatically.
- **Provenance, replay, uncertainty are inherited, not bolted on.** They come
  from the derivation, replay, and `Sample`/`Information` machinery that already
  exists; this LIP wires the training loop into them rather than inventing a
  parallel system.
- **Autodiff is the "match".** PyTorch/JAX train with autodiff; a training
  primitive without it would not be a match. Reverse-mode over the LIP-004
  tensor is the natural fit.
- **Adam/SGD first.** These are the table-stakes optimizers; the optimizer is a
  first-class value so more can be added without changing the surface.

## Compatibility

- **New value types** `VAL_OPTIMIZER`, `VAL_TRAINING_RESULT`.
- **No LABC format change** — `train` and the optimizer constructors are host
  calls, so the bytecode version stays `2`.
- **New host-call IDs** appended to `LanaHostCallId` (C and Rust must match).
- **Depends on LIP-004** (tensors), **LIP-005** (STATE surface, so training
  works over STATE tensors), **LIP-011** (autodiff), and the existing function,
  `lazy`, `Sample`, and `Information` machinery.
- **Resource limits unchanged**; the tape and step history count against the
  256 MiB limit.

## Test coverage

- `sgd`/`adam` reduce a known convex loss (e.g. linear regression) to within a
  tolerance.
- Determinism: two runs with the same seed produce byte-identical results; a
  different seed may differ.
- Provenance: the step history records batch → gradient → update for a small
  run.
- Uncertainty (LIP-008): a training result over uncertain operands carries
  uncertainty; ordinary tensors stay ordinary.
- Errors: wrong `loss` arity, invalid hyperparameters, empty data, non-finite
  loss, unauthorized execution.
- Differential conformance: byte-identical C11 vs Rust output for a fixed seed.
