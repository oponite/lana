# LIP-009: Bayesian inference as a first-class training mode

- **Status:** Draft
- **Author:** Vijay
- **Date:** 2026-09-05

## Motivation

Lana already has the primitives of Bayesian inference — `observe`, `condition`,
`joint`, `sample`, `resolve` (`spec/SPEC.md` "Information and named joints") —
but they are **exact**: they enumerate support, which does not scale to
continuous or high-dimensional models. Python reaches for Pyro, NumPyro, or
Stan, each bolted on and outside the language's provenance and uncertainty
model.

This LIP makes those primitives **scalable and differentiable** by adding MCMC,
variational inference, and SMC as first-class, auditable operations. Then
"training" has two modes: gradient descent (LIP-006) and conditioning on data
(Bayesian). The posterior is a first-class value carrying provenance and
uncertainty, so a Bayesian model is auditable and replayable exactly like every
other Lana value.

## Specification

### 1. Inference algorithms (first-class values)

```lana
let alg = mcmc(samples: 10000, burn_in: 1000);
let alg = vi(family: gaussian, iterations: 1000);
let alg = smc(particles: 1000);
```

- `mcmc` — Markov chain Monte Carlo; `samples` and `burn_in` are positive
  integer literals.
- `vi` — variational inference; `family` names a parametric family
  (`gaussian`, `mean_field`), `iterations` is a positive integer literal.
- `smc` — sequential Monte Carlo; `particles` is a positive integer literal.
- Each is a `VAL_INFERENCE_ALGORITHM` value; more algorithms can be added
  without changing the surface.

### 2. The `infer` operation

```lana
let posterior = infer(prior, model, data, mcmc(samples: 10000));
```

- `prior` is a distribution over parameters; `model` is the likelihood (a
  conditional joint, `joint conditional { params: prior, data: model }`);
  `data` is the observed evidence.
- `infer` conditions the model on `data` and returns a `VAL_POSTERIOR` — a
  distribution over parameters — using the chosen algorithm.
- The exact primitives remain: `condition`/`observe`/`sample`/`resolve` are the
  exact operations; `infer` composes them with an approximate algorithm for
  scalability. `infer` with an exact (enumerated) algorithm is the existing
  `condition`.

### 3. Scalable and differentiable

- **MCMC** and **SMC** are sample-based: they scale to high-dimensional
  posteriors by drawing from them rather than enumerating support.
- **VI** is differentiable: it optimizes the variational parameters by gradient
  descent, reusing the autodiff of LIP-011. The ELBO is the loss; the
  variational parameters are tensors (LIP-004).
- The posterior is an uncertainty-carrying value (LIP-008): its prediction and
  uncertainty are both first-class.

### 4. Provenance, replay, and audit

- Each inference step — an MCMC transition, a VI iteration, an SMC particle
  update — is a derivation node, so the posterior's provenance records *which
  data conditioned which parameter update*.
- The run is seeded; the same `(seed, inputs, version)` reproduces the same
  posterior bytes (§9.7.5).
- The posterior carries its uncertainty (LIP-008) and provenance, so a Bayesian
  model is auditable end to end.

### 5. Errors

| Condition | Error |
|---|---|
| `prior`/`model`/`data` not a distribution / joint / value | `LANA_ERR_TYPE` |
| algorithm hyperparameter not a positive integer | `LANA_ERR_INVALID_PARAMETERS` |
| `vi` family unknown | `LANA_ERR_INVALID_PARAMETERS` |
| inference fails to converge | `LANA_ERR_INVALID_PARAMETERS` |
| empty `data` | `LANA_ERR_INVALID_PARAMETERS` |

## Rationale

- **Native, not bolted on.** Pyro/NumPyro/Stan are external; Lana's inference
  is the same language as the model, so the posterior inherits provenance,
  replay, and uncertainty for free.
- **Two training modes, one surface.** `train` (LIP-006) and `infer` (this LIP)
  are parallel first-class operations; a model is produced from data either by
  optimization or by conditioning, and both are auditable.
- **Scalable without losing exactness.** The exact primitives stay; `infer`
  adds approximate algorithms as an explicit choice, never a silent fallback.

## Compatibility

- **New value types** `VAL_INFERENCE_ALGORITHM`, `VAL_POSTERIOR`.
- **No LABC format change** — operations are host calls, so the bytecode
  version stays `2`.
- **New host-call IDs** appended to `LanaHostCallId` (C and Rust must match).
- **Depends on LIP-004** (tensor), **LIP-006** (training), **LIP-008**
  (uncertainty, for the posterior), and **LIP-011** (autodiff, for VI).
- **Resource limits unchanged**; MCMC chains, VI parameters, and SMC particles
  count against the 256 MiB limit.

## Test coverage

- `mcmc`/`vi`/`smc` recover a known posterior (e.g. a Beta-Bernoulli or
  Gaussian mean) to within a tolerance.
- `vi` is differentiable: the ELBO decreases over iterations.
- Exact recovery: `infer` with an enumerated algorithm matches `condition`.
- Provenance: the posterior traces to its conditioning data.
- Replay: two runs with the same seed produce byte-identical posteriors.
- Errors: unknown `vi` family, non-positive hyperparameters, empty data.
- Differential conformance: byte-identical C11 vs Rust output for a fixed seed.
